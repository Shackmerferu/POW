1 Cómo es el parcial (y qué te van a pedir)

El parcial típico de POW es práctico sobre un proyecto que ya existe: te entregan un sitio (HTML/CSS/JS), una API en PHP, una base MySQL con datos y una carpeta de recursos. No hay que inventar todo: hay que integrar una funcionalidad nueva y, a veces, completar uno o dos archivos PHP que vienen vacíos.

Puede haber dos opciones de front: Opción A (HTML + CSS tradicional + JavaScript puro) o Opción B (Bootstrap y/o jQuery). Elegí una y no mezcles: se evalúa que el resultado funcione, no la cantidad de librerías.

2 Ruta de ataque en 7 pasos

  1. Leer todo el enunciado y subrayar los verbos. Marcá qué es obligatorio, qué es opcional y qué archivos NO se tocan. Anotá los nombres exactos de tablas, columnas y endpoints.
  2. Abrir la base de datos. En phpMyAdmin mirá estructura y algunos registros. Sin entender los datos, cualquier consulta es adivinanza.
  3. Probar la API antes de tocar el front. Pegá cada endpoint en el navegador y mirá el JSON. Si no responde, el problema es del servidor, no de tu JS.
  4. Dibujar el flujo. Evento → fetch → PHP → SQL → JSON → DOM. Escribilo en un papel; te ahorra media hora de depuración.
  5. Maquetar primero con datos fijos. Armá el HTML/CSS con dos o tres tarjetas escritas a mano. Cuando se ve bien, reemplazá por datos reales.
  6. Conectar y renderizar. Traé los datos, vaciá el contenedor y creá los elementos. Manejá el caso “no hay datos” y el error de red.
  7. Probar el flujo completo y recién ahí sumar extras. Recargá, guardá, volvé a entrar, revisá la consola y la pestaña Network. Un extra roto resta más de lo que suma.
Consejo de tiempo: si el parcial dura 3 horas, dedicá 15 minutos a leer y explorar, 90 minutos al punto principal, 45 al segundo punto y 30 a probar/embellecer. Nunca empieces por el CSS.

5. Menú dinámico desde la base front

Cuando el menú no está escrito en el HTML sino en la tabla item_menu.

// config.js
const API = "http://localhost/la_tania/api";

// app.js
async function armarMenu() {
  const nav = document.getElementById("nav");
  if (!nav) return;

  try {
    const res = await fetch(`${API}/menu.php`);
    const data = await res.json();

    nav.innerHTML = "";

    // Solo los visibles (la BD puede traer "SI", "NO" o vacío)
    data.productos
      .filter(item => String(item.visible).trim().toUpperCase() === "SI")
      .forEach(item => {
        const a = document.createElement("a");
        a.textContent = String(item.titulo).toUpperCase();

        const cat = Number(item.id_categoria);
        if (cat === 1) a.href = "canicas_masculino.html";
        else if (cat === 3) a.href = "canicas_femenino.html";
        else a.href = item.src || "index.html";

        nav.appendChild(a);
      });
  } catch (error) {
    console.error("No se pudo armar el menú:", error);
  }
}

document.addEventListener("DOMContentLoaded", armarMenu);

No hardcodees los ítems “porque total son pocos”: el punto del ejercicio suele ser justamente demostrar que salen de la BD.

6. Traer datos con fetch (GET) front

Para listar jugadores, equipos, partidos, novedades o cualquier endpoint que solo consulta.

async function traer(url) {
  const res = await fetch(url);
  if (!res.ok) throw new Error("HTTP " + res.status);

  const data = await res.json();

  // La API del parcial responde { status, cantidad, productos }
  if (Number(data.status) !== 200) {
    throw new Error(data.mensaje || "La API devolvió un error");
  }
  return data.productos ?? data;
}

async function cargarJugadores() {
  const cont = document.getElementById("jugadores");
  cont.innerHTML = "<p>Cargando…</p>";

  try {
    const filas = await traer(`${API}/jugadores.php?id_categoria=1`);

    // Sin repetidos: un jugador puede estar en varias categorías
    const unicos = [...new Map(filas.map(j => [j.dni, j])).values()];

    cont.innerHTML = "";
    if (unicos.length === 0) {
      cont.innerHTML = "<p>No hay jugadores cargados.</p>";
      return;
    }

    unicos.forEach(j => {
      const card = document.createElement("article");
      card.className = "card";

      card.innerHTML = `
        <img src="${API}/img/jugadores/${j.imagen}" alt="${j.nombre} ${j.apellido}">
        <h3>${j.nombre} ${j.apellido}</h3>
        <p>"${j.apodo || ""}"</p>
        <button type="button">Ver más</button>
      `;

      card.querySelector("button").addEventListener("click", () => abrirModal(j));
      cont.appendChild(card);
    });
  } catch (error) {
    cont.innerHTML = `<p class="error">No se pudo cargar: ${error.message}</p>`;
    console.error(error);
  }
}

Siempre contemplá tres estados: cargando, vacío y error. Es lo primero que mira un corrector.

7. Guardar datos con fetch (POST) front

Para agregar un palmarés, un comentario, una inscripción o cualquier alta simple.

async function guardar(dni, anio, detalle) {
  const params = new URLSearchParams({ dni, anio, detalle });

  const res = await fetch(`${API}/palmares_guardar.php`, {
    method: "POST",
    headers: { "Content-Type": "application/x-www-form-urlencoded" },
    body: params
  });

  const data = await res.json();

  if (Number(data.status) === 200) {
    alert(data.mensaje || "Guardado");
    // Refrescar la lista para ver el dato nuevo:
    // await cargarPalmares(dni);
  } else {
    alert(data.mensaje || "No se pudo guardar");
  }
}

// Uso desde un formulario
formulario.addEventListener("submit", async (e) => {
  e.preventDefault();
  await guardar(dni, anio, detalle);
});

Si el PHP espera $_POST, usá application/x-www-form-urlencoded o FormData. Si le mandás JSON crudo, el PHP tiene que leer php://input.

8. Subir archivo con FormData front

Para logos, fotos de jugadores o cualquier archivo que deba quedar en el servidor.

<form id="formClub">
  <input id="nombre" name="nombre" required>
  <input id="logo" name="logo" type="file" accept="image/*" required>
  <button>Guardar club</button>
  <p id="msg"></p>
</form>

<script>
const formClub = document.getElementById("formClub");

formClub.addEventListener("submit", async (e) => {
  e.preventDefault();

  const fd = new FormData();
  fd.append("nombre", document.getElementById("nombre").value);
  fd.append("logo", document.getElementById("logo").files[0]);

  try {
    const res = await fetch(`${API}/equipos_insertar.php`, {
      method: "POST",
      body: fd
      // NO pongas Content-Type: fetch agrega el boundary solo
    });

    const data = await res.json();
    document.getElementById("msg").textContent = data.mensaje;
  } catch (error) {
    document.getElementById("msg").textContent = "Error de conexión";
    console.error(error);
  }
});
</script>

Errores clásicos: poner Content-Type: multipart/form-data a mano (rompe el boundary), olvidar el name del input o no usar type="file".

    e.preventDefault();

.serialize() no sirve para archivos. Para subir imágenes con jQuery usá FormData y processData: false, contentType: false.

Back-end

11. PHP: endpoint JSON + conexión back

Base de cualquier archivo PHP que la API vaya a consumir con fetch.

<?php
// IMPORTANTE: nada de espacios ni líneas en blanco antes de <?php.
// Un solo espacio rompe el JSON y el front falla con "Unexpected token".

header("Access-Control-Allow-Origin: *");
header("Access-Control-Allow-Headers: Content-Type");
header("Content-Type: application/json; charset=utf-8");

// conexion.php define las variables de conexión
require __DIR__ . "/conexion.php";

$conexion = mysqli_connect($server_db, $usuario_db, $password_db);
if (!$conexion) {
    echo json_encode(["status" => 500, "mensaje" => "No se pudo conectar"]);
    exit;
}

mysqli_select_db($conexion, $base_db);
mysqli_set_charset($conexion, "utf8mb4");

En XAMPP el usuario suele ser root sin contraseña y el servidor localhost. Si cambiás de máquina, revisá conexion.php antes que nada.

12. PHP: SELECT que devuelve JSON back

Para cualquier listado con filtro, por ejemplo jugadores por categoría.

<?php
// ... conexión y headers de la receta 11 ...

$cat = (int) ($_GET["id_categoria"] ?? 0);

$sql = "SELECT id_jugador, nombre, apellido, apodo, dni, biografia, imagen
        FROM jugadores
        WHERE id_categoria = $cat";

$res = mysqli_query($conexion, $sql);
if (!$res) {
    echo json_encode([
        "status" => 500,
        "mensaje" => mysqli_error($conexion)
    ]);
    exit;
}

$filas = [];
while ($fila = mysqli_fetch_assoc($res)) {
    $filas[] = $fila;
}

echo json_encode([
    "status" => 200,
    "cantidad" => count($filas),
    "productos" => $filas
], JSON_UNESCAPED_UNICODE);

mysqli_close($conexion);

Respetá la forma de respuesta que ya usa la API del parcial: { status, cantidad, productos }. Si inventás otra, el front existente deja de funcionar.

13. PHP: INSERT seguro back

Para guardar un registro que llega por POST.

<?php
// ... conexión y headers de la receta 11 ...

$dni     = trim($_POST["dni"] ?? "");
$detalle = trim($_POST["detalle"] ?? "");
$anio    = (int) ($_POST["anio"] ?? date("Y"));

// Validar antes de tocar la base
if ($dni === "" || $detalle === "") {
    echo json_encode([
        "status" => 500,
        "mensaje" => "Faltan datos obligatorios"
    ]);
    exit;
}

// Prepared statement: evita inyección SQL
$sql = "INSERT INTO palmares (dni, anio, detalle) VALUES (?, ?, ?)";
$stmt = mysqli_prepare($conexion, $sql);
mysqli_stmt_bind_param($stmt, "sis", $dni, $anio, $detalle);
// "s" = string, "i" = integer, "d" = decimal

if (mysqli_stmt_execute($stmt)) {
    echo json_encode([
        "status" => 200,
        "mensaje" => "Guardado correctamente",
        "id" => mysqli_insert_id($conexion)
    ]);
} else {
    echo json_encode([
        "status" => 500,
        "mensaje" => mysqli_error($conexion)
    ]);
}

Si usás la versión con mysqli_real_escape_string(), escapá todos los strings y casteá los números. La prepared statement es más segura y más corta.

14. PHP: subida de archivos back

Para logos, fotos o cualquier archivo que llegue por FormData.

<?php
// ... conexión y headers de la receta 11 ...

if (!isset($_FILES["logo"]) || $_FILES["logo"]["error"] !== UPLOAD_ERR_OK) {
    echo json_encode(["status" => 500, "mensaje" => "No llegó el archivo"]);
    exit;
}

$archivo = $_FILES["logo"];
$permitidas = ["jpg", "jpeg", "png", "gif", "webp"];
$ext = strtolower(pathinfo($archivo["name"], PATHINFO_EXTENSION));

if (!in_array($ext, $permitidas, true)) {
    echo json_encode(["status" => 500, "mensaje" => "Extensión no permitida"]);
    exit;
}

if ($archivo["size"] > 2 * 1024 * 1024) {
    echo json_encode(["status" => 500, "mensaje" => "El archivo supera 2 MB"]);
    exit;
}

$carpeta = __DIR__ . "/img/logos/";
if (!is_dir($carpeta)) {
    mkdir($carpeta, 0777, true);
}

$nombreArchivo = uniqid("logo_") . "." . $ext;

if (!move_uploaded_file($archivo["tmp_name"], $carpeta . $nombreArchivo)) {
    echo json_encode(["status" => 500, "mensaje" => "No se pudo guardar"]);
    exit;
}

// En la base guardás SOLO el nombre; la URL se arma al mostrar
$nombre = trim($_POST["nombre"] ?? "");
if ($nombre === "") {
    echo json_encode(["status" => 500, "mensaje" => "Falta el nombre del club"]);
    exit;
}

$sql = "INSERT INTO equipos (nombre, logo, puntos) VALUES (?, ?, 0)";
$stmt = mysqli_prepare($conexion, $sql);
mysqli_stmt_bind_param($stmt, "ss", $nombre, $nombreArchivo);
mysqli_stmt_execute($stmt);

echo json_encode([
    "status" => 200,
    "mensaje" => "Club guardado con el logo $nombreArchivo"
]);

Si el archivo no llega, revisá upload_max_filesize y post_max_size en php.ini, que la carpeta tenga permisos y que el input tenga name="logo".

15. PHP: sesiones y login back

Para restringir páginas o recordar al usuario logueado.

<?php
// login.php (después de validar usuario y contraseña)
session_start();
$_SESSION["usuario"] = $usuario;
$_SESSION["rol"] = "admin";
header("Location: panel.php");
exit;
<?php
// panel.php (proteger la página)
session_start();
if (!isset($_SESSION["usuario"])) {
    header("Location: login.php");
    exit;
}
echo "Hola, " . htmlspecialchars($_SESSION["usuario"]);
<?php
// logout.php

session_destroy();
header("Location: login.php");

session_start() va antes de cualquier salida HTML. La sesión vive en el servidor; la cookie solo guarda el identificador.

16. MySQL: las consultas que necesitás back

Chuleta para phpMyAdmin o para pegar dentro de PHP.

-- Listar con filtro y orden
SELECT nombre, apellido FROM jugadores
WHERE id_categoria = 1
ORDER BY apellido ASC;

-- Buscar texto
SELECT * FROM equipos WHERE nombre LIKE '%tania%';

-- Insertar
INSERT INTO equipos (nombre, logo, puntos)
VALUES ('Nuevo Club', 'logo.png', 0);

-- Actualizar (¡siempre con WHERE!)
UPDATE equipos SET puntos = 3 WHERE id_equipo = 2;

-- Borrar (¡siempre con WHERE!)
DELETE FROM palmares WHERE id = 5;

-- Contar / agrupar
SELECT id_categoria, COUNT(*) AS total
FROM jugadores
GROUP BY id_categoria;

-- Unir tablas
SELECT j.nombre, p.anio, p.detalle
FROM jugadores j
JOIN palmares p ON p.dni = j.dni
WHERE j.dni = '1';

-- Top 5
SELECT nombre, puntos FROM equipos
ORDER BY puntos DESC
LIMIT 5;

Antes de escribir la consulta en PHP, probala en phpMyAdmin. Si ahí funciona y en PHP no, el problema es de conexión, comillas o nombre de columna.

17. Node: servidor mínimo extra

Solo si el enunciado o la cátedra pide Node en lugar de PHP/Apache.

// servidor.js  →  node servidor.js
const http = require("http");
const fs = require("fs");

const server = http.createServer((req, res) => {
  if (req.url === "/datos") {
    res.writeHead(200, { "Content-Type": "application/json; charset=utf-8" });
    res.end(fs.readFileSync("datos.json", "utf8"));
    return;
  }

  res.writeHead(200, { "Content-Type": "text/html; charset=utf-8" });
  res.end(fs.readFileSync("index.html", "utf8"));
});

server.listen(3000, () => {
  console.log("Servidor en http://localhost:3000");
});

En Node no hay $_POST ni $_FILES: para leer el cuerpo de un POST hay que juntar los chunks del request (req.on("data") / req.on("end")) o usar Express + express.json().

18. XMLHttpRequest clásico si lo exigen

Si el enunciado pide explícitamente XMLHttpRequest en lugar de fetch. Es la técnica original de AJAX.

// GET
const xhr = new XMLHttpRequest();
xhr.open("GET", `${API}/jugadores.php?id_categoria=1`, true);

xhr.onreadystatechange = function () {
  if (xhr.readyState !== 4) return;   // 4 = petición terminada
  if (xhr.status !== 200) {
    console.error("HTTP", xhr.status);
    return;
  }
  const data = JSON.parse(xhr.responseText);
  console.log(data.productos);
};

xhr.send();

// POST de formulario
const xhr2 = new XMLHttpRequest();
xhr2.open("POST", `${API}/palmares_guardar.php`, true);
xhr2.setRequestHeader("Content-Type", "application/x-www-form-urlencoded");

xhr2.onload = function () {
  if (xhr2.status === 200) {
    console.log(JSON.parse(xhr2.responseText));
  }
};

xhr2.send("dni=1&anio=2026&detalle=Campe%C3%B3n");

readyState va de 0 a 4 (4 = completado) y status es el código HTTP. Si usás onload, no hace falta preguntar por readyState.

6 Protocolo de depuración (en orden)

  1. Consola (F12 → Console). Cualquier texto rojo es tu primera pista: archivo y línea exactos.
  2. Network. Mirá la petición: URL, método, status, payload enviado y respuesta cruda. El 90% de los bugs de AJAX se ve acá.
  3. Abrí el endpoint directo en el navegador. Si ahí falla, el problema es del PHP o de la base, no del front.
  4. Mostrá los errores de PHP en desarrollo. Arriba del archivo: ini_set("display_errors", 1); error_reporting(E_ALL);. Acordate de sacarlo después.
  5. Inspeccioná lo que llega. var_dump($_POST, $_GET, $_FILES); y, si mandás JSON, file_get_contents("php://input").
  6. Probá la consulta en phpMyAdmin. Aislás el problema de SQL del problema de PHP.
  7. Recargá sin caché (Ctrl+F5) y volvé a probar en una ventana incógnito. Muchos “no se actualiza” son caché.
Truco: cuando algo no funciona, comentá todo y andá agregando de a una capa: HTML → CSS → datos fijos → fetch → PHP → SQL. La primera capa que falla es el bug.

7 Preguntas teóricas probables

Respuestas cortas para defender el código. Si querés el desarrollo completo, cada tema está en su unidad.

PreguntaRespuesta mínima
¿Qué es AJAX?Técnica para comunicarse con el servidor de forma asíncrona sin recargar la página; combina HTML/CSS, DOM, JSON/XML, XMLHttpRequest/fetch y JavaScript.
GET vs POSTGET envía datos en la URL (visible, limitado, cacheable) y se usa para consultar. POST los envía en el cuerpo (más privado, sin límite práctico) y se usa para crear/modificar.
== vs ===== compara con conversión de tipos; === compara valor y tipo. Usá siempre ===.
var vs let vs constvar tiene alcance de función y hoisting; let y const tienen alcance de bloque. const no permite reasignar la variable.
id vs classid es único en la página y se selecciona con #; class se repite y se selecciona con ..
Box modelCada elemento es contenido + padding + border + margin. box-sizing: border-box incluye padding y border en el ancho declarado.
Especificidad CSSEstilos en línea > id > clase/atributo/pseudo-clase > elemento. A igual especificidad gana la última regla; !important rompe la cascada.
position: relative / absolute / fixed / stickyrelative se mueve respecto de su lugar; absolute respecto del ancestro posicionado; fixed respecto de la ventana; sticky se fija al hacer scroll.
Flexbox vs GridFlexbox distribuye en un eje (fila o columna); Grid maneja filas y columnas a la vez. Grid para layouts completos, Flex para alinear componentes.
¿Qué es el DOM?La representación en árbol del documento HTML que el navegador expone a JavaScript para leer y modificar la página.
¿Qué es un evento y qué es bubbling?Una acción del usuario o del navegador. Bubbling es la propagación del evento desde el elemento hijo hacia sus ancestros; se puede cortar con stopPropagation().
¿Qué es JSON?Formato de texto para intercambiar datos, con pares clave-valor y arrays. En JS se pasa con JSON.parse()/JSON.stringify(); en PHP con json_decode()/json_encode().
Cookie vs sesiónLa cookie se guarda en el cliente y viaja en cada request; la sesión se guarda en el servidor y el cliente solo conserva un identificador.
include vs requireAmbos insertan un archivo; require produce un error fatal si falla y include solo un warning. Para archivos críticos usá require.
mysqli vs PDOAmbos acceden a MySQL. mysqli es específico de MySQL; PDO es una interfaz única para varias bases. Los dos soportan prepared statements.
¿Qué es la inyección SQL y cómo se evita?Es colar SQL malicioso a través de datos del usuario. Se evita con prepared statements y validación/escape, nunca concatenando input sin controlar.
¿Para qué sirve header("Content-Type: application/json")?Le dice al cliente que la respuesta es JSON para que res.json() la interprete correctamente.
Status HTTP 200 / 404 / 500200 OK; 404 recurso no encontrado; 500 error interno del servidor (por ejemplo, un PHP que falla).
¿Qué es responsive?Diseño que se adapta al tamaño de pantalla usando viewport, unidades flexibles, media queries y/o grillas.
¿Qué es CORS?Política del navegador que bloquea pedidos entre orígenes distintos si el servidor no envía los headers Access-Control-Allow-*.
¿Qué hace move_uploaded_file()?Mueve el archivo temporal subido ($_FILES["campo"]["tmp_name"]) a una carpeta del servidor con el nombre definitivo.
¿Por qué $_FILES["logo"]["error"] === 0?Porque 0 (UPLOAD_ERR_OK) indica que la subida terminó bien; cualquier otro valor es un error.

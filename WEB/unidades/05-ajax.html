Unidad 5 · AJAX

AJAX (Asynchronous JavaScript + XML) no es un lenguaje ni una tecnología en sí misma: es una técnica que combina varias tecnologías para que la página se comunique con el servidor en segundo plano, sin recargarse. Así se crean las RIA (Rich Internet Applications).

Nota: AJAX necesita un servidor y, por seguridad, los navegadores bloquean XMLHttpRequest a archivos locales cuando la página se abre con file://. Por eso en esta unidad los ejemplos se muestran sobre fetch(), que es la forma moderna y funciona con el mismo principio.

1. Qué es AJAX y qué tecnologías combina

AJAX permite solicitar datos al servidor y cargarlos en segundo plano sin interferir con la visualización ni el comportamiento de la página. Está basado en estándares abiertos, así que funciona en múltiples plataformas, sistemas operativos y navegadores.

No es una tecnología única: es la unión de varias que, combinadas, producen el efecto asíncrono.

TecnologíaRol dentro de AJAX
XHTML / HTML y CSSPresentación basada en estándares.
DOMInteracción y manipulación dinámica de la presentación.
XML, XSLT y JSONIntercambio y manipulación de información (también texto plano).
XMLHttpRequestIntercambio asíncrono de información.
JavaScriptUne todas las demás tecnologías (con ASP, PHP, etc.).
Esquema de funcionamiento 
BROWSER                                  SERVER
   │  1. Ocurre un evento (click, keyup…)
   │  2. Se crea el objeto XMLHttpRequest
   │─── 3. Envía HttpRequest  ─────────────▶
   │                                        4. Procesa el request

   │      (en segundo plano)
   │  6. Procesa lo recibido con JavaScript
   │  7. Actualiza el contenido de la página

2. Modelo tradicional vs AJAX

En el modelo tradicional cada acción del usuario (clic en un botón, elegir de una lista) genera una llamada al servidor; el servidor responde con una página HTML nueva y el usuario debe esperar a que se recargue por completo.

En el modelo AJAX se interpone una capa entre el usuario y el servidor: la petición se procesa en segundo plano y solo se actualiza la parte de la página que cambió. Desaparece la ventana en blanco y la espera.

AspectoModelo tradicionalModelo AJAX
ComunicaciónRecarga completa de la página.Asíncrona, en segundo plano.
Datos que viajanEl HTML entero.Solo los datos necesarios (JSON/XML/texto).
Espera del usuarioPantalla en blanco hasta recibir respuesta.La página sigue usable.
SensaciónSaltos de página.Aplicación de escritorio (RIA).
Ejemplo · el contraste en código 
<!-- Tradicional: un formulario recarga toda la página -->
<form action="buscar.php" method="post">
  <input name="q"><button>Buscar</button>
</form>

<!-- AJAX: se trae solo la respuesta y se inyecta -->
<input id="q">
<button onclick="buscar()">Buscar</button>
<div id="resultado"></div>

<script>
  function buscar() {
    const q = document.getElementById("q").value;
    fetch("buscar.php?q=" + encodeURIComponent(q))
      .then(r => r.text())
      .then(txt => document.getElementById("resultado").innerHTML = txt);
  }
</script>
Resultado · el texto se inyecta sin recargar

3. El objeto XMLHttpRequest

XMLHttpRequest (XHR) es el corazón de AJAX: es el objeto del navegador que hace la petición HTTP en segundo plano. Se crea con new XMLHttpRequest() y luego se configura y se envía.

La respuesta se atiende mediante el evento onreadystatechange (o el más moderno onload), que se dispara a medida que cambia el estado de la petición.

Propiedad / métodoQué es
new XMLHttpRequest()Crea el objeto.
open(metodo, url, asinc)Configura la petición. asinc suele ser true.
send(datos)Envía la petición.
setRequestHeader()Agrega cabeceras (por ejemplo Content-Type).
readyStateEstado de la petición (0 a 4).
statusCódigo HTTP de la respuesta (200 = OK, 404 = no encontrado).
responseText / responseXMLLa respuesta como texto o como XML.
Ejemplo · petición asíncrona completa 
const xhttp = new XMLHttpRequest();

xhttp.onreadystatechange = function () {
  if (this.readyState === 4 && this.status === 200) {
    document.getElementById("demo").innerHTML = this.responseText;
  }
};

xhttp.open("GET", "datos.txt", true);   // true = asíncrono
xhttp.send();

4. readyState, status y cómo trabaja

readyState indica en qué etapa va la petición, mientras que status es el código HTTP que devolvió el servidor. La receta habitual es actuar cuando readyState === 4 (todo terminó) y status === 200 (salió bien).

readyStateSignifica
0UNSENT: el objeto está creado, todavía no se llamó a open().
1OPENED: send() aún no fue llamado.
2HEADERS_RECEIVED: send() ya fue llamado, llegaron las cabeceras.
3LOADING: descargando el cuerpo de la respuesta.
4DONE: la operación terminó.
statusSignifica
200OK: respuesta correcta.
404Recurso no encontrado.
500Error del servidor.
Ejemplo · seguir los estados 
<button id="go">Enviar</button>
<pre id="log"></pre>

<script>
  document.getElementById("go").addEventListener("click", function () {
    const x = new XMLHttpRequest();
    x.onreadystatechange = function () {
      document.getElementById("log").textContent +=
        "readyState = " + this.readyState + "\n";
      if (this.readyState === 4 && this.status === 200) {
        document.getElementById("log").textContent += "¡Respuesta recibida!";
      }
    };
    x.open("GET", "datos.txt", true);
    x.send();
  });
</script>

5. Métodos open() y send(); GET vs POST

open() configura la petición indicando el método HTTP, la URL y si es asíncrona. send() la envía: con GET va sin argumentos, con POST se le pasan los datos.

GET escribe los datos en la URL (visible, limitado en tamaño, se puede cachear). POST los envía en el cuerpo (no visible, sin límite práctico, nunca se cachea).

GETPOST
Dónde van los datosEn la URL (?a=1&b=2)En el cuerpo de la petición
Visible en la barraSíNo
CachéPuede guardarseNunca
Uso típicoConsultas, filtros, búsquedasAltas, login, datos sensibles
Ejemplo 
// --- GET ---
const x1 = new XMLHttpRequest();
x1.open("GET", "buscar.php?q=" + encodeURIComponent(texto), true);
x1.send();

// --- POST ---
const x2 = new XMLHttpRequest();
x2.open("POST", "guardar.php", true);
x2.setRequestHeader("Content-Type", "application/x-www-form-urlencoded");
x2.send("nombre=Ana&edad=22");

6. Respuestas: texto, XML y JSON

El servidor puede devolver la información en distintos formatos. responseText siempre trae la respuesta como cadena; responseXML la interpreta como documento XML y permite recorrerla con el DOM. Hoy lo más común es JSON, que se convierte a objeto con JSON.parse() (y a texto con JSON.stringify()).

Ejemplo 
// JSON que devuelve el servidor:
// {"nombre":"Ana","edad":22}

const x = new XMLHttpRequest();
x.onreadystatechange = function () {
  if (this.readyState === 4 && this.status === 200) {
    const datos = JSON.parse(this.responseText);   // texto → objeto
    document.getElementById("out").textContent =
      datos.nombre + " tiene " + datos.edad + " años";
  }
};
x.open("GET", "persona.php", true);
x.send();

// Y al revés: objeto → texto
// JSON.stringify({ a: 1, b: 2 })   →  '{"a":1,"b":2}'

7. Validar un formulario con AJAX

Un uso típico de AJAX es la validación en vivo: mientras el usuario escribe, se envía el dato al servidor y este responde si está disponible (por ejemplo, si un nickname ya existe) sin recargar. Se dispara con el evento keyup y se inyecta la respuesta en un <div>.

Ejemplo 
<input id="nick" placeholder="Elegí un nickname">
<div id="mensaje"></div>

<script>
  document.getElementById("nick").addEventListener("keyup", function () {
    const valor = this.value;
    const x = new XMLHttpRequest();
    x.onreadystatechange = function () {
      if (this.readyState === 4 && this.status === 200) {
        document.getElementById("mensaje").innerHTML = this.responseText;
      }
    };
    x.open("POST", "comprobar_nick.php", true);
    x.setRequestHeader("Content-Type", "application/x-www-form-urlencoded");
    x.send("nickname=" + encodeURIComponent(valor));
  });
</script>

8. Fetch API y async/await

Fetch es la forma moderna de hacer AJAX. Reemplaza a XMLHttpRequest con una función que devuelve una promesa. El resultado se maneja con .then() o, más cómodo, con async/await y try/catch. Hay que recordar convertir la respuesta: res.text() o res.json().

Ejemplo 
// Con .then()
fetch("datos.json")
  .then(res => {
    if (!res.ok) throw new Error("Error " + res.status);
    return res.json();
  })
  .then(datos => console.log(datos))
  .catch(err => console.error(err));

// Con async/await
async function cargar() {
  try {
    const res = await fetch("datos.json");
    const datos = await res.json();
    document.getElementById("out").textContent = datos.titulo;
  } catch (e) {
    console.error("Falló la petición:", e);
  }
}
cargar();
Resultado · petición real a una API pública
